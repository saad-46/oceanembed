# OceanSight frontend

Next.js (App Router) + TypeScript + Tailwind + MapLibre GL + deck.gl + Recharts. Spec: `../docs/12_UI_UX_SPECIFICATION.md`.

```bash
npm install
cp .env.example .env.local      # NEXT_PUBLIC_API_URL (default http://localhost:8100)
npm run dev                     # http://localhost:3100
npm run build                   # production build (NEXT_PUBLIC_API_URL optional; without it the browser discovers a local API)
npm run lint && npm run typecheck && npm test
```

- The build is `output: "standalone"`, so `next start` is not supported. Serve it as `docker/frontend.Dockerfile`
  does: copy `.next/static` to `.next/standalone/.next/static` and `public/` to `.next/standalone/public`, then
  `PORT=3100 node .next/standalone/server.js`.

- Deploying to Vercel (Root Directory `frontend`; `NEXT_PUBLIC_API_URL` unset, or a deployed backend URL): see
  `../docs/VERCEL_DEPLOYMENT.md`. Never set it to `localhost` on Vercel.

- Basemap is fully offline: clipped Natural Earth GeoJSON in `public/geo/` (no tile CDN).
- Online / offline is decided in the browser by `lib/connection.ts` (one store, one 20 s poller): an explicit
  `NEXT_PUBLIC_API_URL`, or else the API on the visitor's own computer, permission-aware. While offline,
  `lib/api.ts` answers from the bundled snapshots in `public/fallback/` (generated by
  `../scripts/snapshot_fallback.py`) and labels the view "Saved data". See `../docs/VERCEL_DEPLOYMENT.md`.
- Screens: `/` landing · `/overview` · `/map` ocean map + profile drawer · `/3d` · `/profiles` · `/timeline` ·
  `/section` · `/stratification` · `/ts` · `/analysis` region stats + ocean heat along cyclone tracks ·
  `/validation` · `/data-quality` · `/provenance` · `/insights` · `/reports` · `/methodology` · `/guide`.
